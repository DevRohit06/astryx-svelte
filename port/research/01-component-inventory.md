**How to read "port unit".** Astryx ships one directory per component; the directory is the
atomic unit of the port because sub-components (`TableCell`, `SideNavItem`, `ChatComposer`…)
share private context and stylex sheets with their parent and cannot be moved independently.
All counts below are per-directory unless stated otherwise.

### 2.4 `src/Layer/` — 978 LOC · **the single most important primitive**

Every overlay in the system (Popover, Tooltip, HoverCard, DropdownMenu, ContextMenu, Selector,
MultiSelector, Typeahead, Toast, MobileNav, TabList overflow, SideNav flyout) routes through it.

| File | LOC | Role |
|---|---|---|
| `useLayer.tsx` | 632 | The hook. Two modes: `context` (CSS **anchor positioning** against a trigger ref) and `fixed` (explicit x/y). Returns `{ref, anchorId, show, hide, isOpen, id, render}`. `render()` is a **render-prop returning ReactNode** — the key API that has no direct Svelte analogue (see §6). |
| `LayerProvider.tsx` | 63 | App-level provider; owns the toast viewport config. |
| `LayerContext.ts` | 57 | Context for nesting/stacking. |
| `anchorName.ts` | 46 | Generates unique `--anchor-*` CSS anchor names. |
| `layerAnimations.stylex.ts` | 109 | Shared entry/exit keyframes. |

`useLayer` params: `mode: 'context' | 'fixed'` (required), `onShow`, `onHide`, `lightDismiss` (default `false`).
Positioning is done in **pure CSS** via `position-area` / `anchor()` with logical keywords, so RTL
mirrors for free. Native **Popover API** (`popover` attribute + light dismiss) does the layering —
there is no JS floating-ui-style positioning engine to port. This is good news: the hard part is
CSS, and the CSS moves over unchanged.

### 2.8 Recommended foundation build order

```
  1. BaseProps + naming + config          (types & class-name contract)
  2. theme/tokens.stylex → CSS variables  (unblocks literally everything)
  3. utils/*  (pure: plainDate, timeParser, dateParser, color, groupItems,
              inputAria, getKey, composeEventHandlers, sharedResizeObserver,
              themeProps)   ← themeProps + mergeProps need a Svelte redesign
  4. theme/  (defineTheme, generateThemeRules, expand*Scale, hct, Theme,
              MediaTheme, SyntaxTheme, useTheme)
  5. i18n/   (provider + useTranslator + resolve)
  6. SizeContext, InteractiveRoleContext   (Svelte context modules)
  7. hooks/  simple first: useMediaQuery, useScrollLock, useScrollOverflow,
              useInputContainer, useLongPress, useInteractiveRole,
              focusableSelector, useAnnounce, useEntryAnimation,
              useStreamingText, useTypeahead, useHotkeys, useKeyboardHint,
              useClickableContainer, useImageMode, useMenuHover, useOverflow
              then the focus family: useFocusTrap, useListFocus,
              useGridFocus, useTreeFocus
  8. Layer/  (useLayer + LayerProvider + anchorName + layerAnimations)
```

## 4. Dependency graph & topological build order

Edges are **value imports between component directories only** (type-only imports and imports
of shared primitives are excluded — they do not constrain build order once §2 is done).

### 4.1 Mutually-recursive clusters (must be ported together)

Five strongly-connected components exist. Each pair/cluster imports each other and cannot be
sequenced — port the whole cluster in one PR.

| Cluster | Why it cycles |
|---|---|
| `Layout` ↔ `Stack` | `Stack`/`HStack`/`VStack`/`StackItem` are *implemented inside* `Layout/` and re-exported; `Layout` composes them. |
| `Button` ↔ `ButtonGroup` | Button reads `useButtonGroup()`; ButtonGroup `cloneElement`s Buttons. |
| `Avatar` ↔ `AvatarGroup` | Avatar reads group context for stacking/size; group renders Avatars + overflow. |
| `CheckboxInput` ↔ `CheckboxList` | List owns tri-state; input reports up through list context. |
| `AppShell` ↔ `MobileNav` ↔ `SideNav` ↔ `TopNav` | AppShell orchestrates the three navs; each reads AppShell context to know its responsive mode. **The single biggest port unit by coupling.** |

imperative/canvas DOM work, animation, and i18n:

| Rating | Meaning |
|---|---|
| **trivial** | Markup + style props only. No state, no effects, no focus work. A day or less. |

| **very hard** | Several of the above **and** a large surface (>1,500 LOC), a plugin architecture, canvas, or a hand-written parser. Needs its own mini-plan. |

## 6. React-specific patterns with no clean Svelte equivalent

These need an explicit architectural decision **before** M1, because they change the shape of
every component signature.

### 6.1 StyleX — the styling engine (blocking, affects all 96 units)

204 source files import `@stylexjs/stylex`. Components call `stylex.create({...})` and spread
`stylex.props(styles.a, styles.b, xstyle)` onto elements. Crucially, **`xstyle` is a public prop
on `BaseProps`, i.e. on every component** — consumers pass StyleX style objects in.

Options:

| Option | Pros | Cons |
|---|---|---|
| Keep StyleX, compile at build time | Byte-identical CSS; `xstyle` API preserved | StyleX's babel/rollup plugin is React-oriented; needs a Svelte preprocessor; SSR class extraction is unproven |
| Compile the upstream StyleX output to static CSS once, ship `.css` + `data-*` selectors | Zero runtime; matches `themeProps()`/`astryx-*` contract already in place | `xstyle` prop must be dropped or reimplemented as `class`/`style` |
| Rewrite styles as Svelte `<style>` blocks + CSS custom properties | Idiomatic; scoped by default | Large manual effort; risks visual drift from upstream |

**Recommendation to evaluate:** the second — the library already emits stable `astryx-*` class
names and reflects visual props as `data-*` attributes (that is what `themeProps()` does and what
`defineTheme` targets with `@scope`). That contract is framework-agnostic, so the CSS can be
lifted wholesale and `xstyle` replaced with `class`/`style` passthrough.

### 6.2 `useLayer().render(children, props)` — a render prop returning `ReactNode`

`useLayer` returns a `render` function that the caller invokes with children and positioning
props, and whose return value is placed in the tree. Svelte has no "function returning markup"
— `Snippet`s are close but cannot be *returned from* a plain function called during setup.

Decision needed: expose `<Layer>` as a component with a `children` snippet and `bind:` state
(idiomatic), while keeping a `useLayer()`-shaped rune for imperative control (`show`, `hide`,
`isOpen`, `anchorId`). Affects Popover, Tooltip, HoverCard, DropdownMenu, ContextMenu, Toast,
Selector, MultiSelector, Typeahead, Carousel, Tokenizer, PowerSearch, SideNav.

### 6.3 `useOptimistic` + `useTransition` async form actions (15 components)

`Button`, `CheckboxInput`, `CheckboxList`, `CommandPalette`, `DateInput`, `DateRangeInput`,
`DateTimeInput`, `MultiSelector`, `Pagination`, `Selector`, `Switch`, `TextArea`, `TextInput`,
`TimeInput`, `ToggleButton` all accept an async change handler, show the new value immediately,
and **revert automatically when the action settles**, with a pending state during flight.

Svelte has no `useOptimistic`. This must be built as a shared rune — something like
`createOptimistic(initial)` returning `{value, pending, run(promise, optimisticValue)}` — and it
is a prerequisite for M3. Getting this wrong silently breaks the async-action contract of half
the form library.

> **Corrected while building it** (`internal/optimistic.svelte.ts`; see `TODO.md`). This
> section originally said the value reverts "if the promise rejects". That is the visible
> effect, not the mechanism: React drops the override when the *transition ends*, whatever
> the outcome — a success only looks like no revert because the parent has meanwhile
> committed the same value. Written as originally stated, a rejected action's optimistic
> value would persist indefinitely under an uncontrolled parent.
>
> The section also omits the second property, which upstream's `Pagination.test.tsx:600-735`
> pins explicitly: **overlapping actions interrupt rather than queue or drop.** Two rapid
> clicks give `1 → 2 → 3` with two calls, each derived from the optimistic value — so there
> is deliberately *no* re-entry guard, unlike `Button`'s `clickAction`, and the override is
> dropped on an in-flight count reaching zero rather than on a boolean.
>
> `Button` is listed above but in fact uses only `useTransition`; it has no `useOptimistic`.
> The count of components genuinely needing this is one lower than the heading says.

### 6.4 `cloneElement` / `Children.map` child introspection (9 sites)

| Site | What it does |
|---|---|
| `ButtonGroup` | Clones child Buttons to inject group position/size. |
| `Tooltip` | Clones the single trigger child to attach ref + ARIA. |
| `TreeList` | Clones nodes to inject depth/expanded state. |
| `Carousel` | Counts and slices children into slides. |
| `MetadataList` | Introspects children to build the definition list. |
| `OverflowList` | Slices children by measured overflow. |
| `PowerSearchEditPopover` | Dispatches on child type. |
| `hooks/useOverflow` | Maps over children to measure each. |
| `AppShell` | `isValidElement` checks to identify which nav slots were provided. |

Svelte cannot inspect or clone snippet content. Every one of these must be re-expressed as an
explicit data-driven API (`items={...}`) or as context that children *read* rather than have
*injected*. **`Tooltip`'s trigger-cloning is the highest-traffic case** (24 dependents) — decide
between a `{#snippet trigger()}` + wrapper element, or an `use:tooltip` action.

### 6.5 `mergeProps` / `mergeRefs` / `forwardRef`

`mergeProps()` (110 LOC) merges className, style, event handlers and refs from multiple sources
— the standard headless-UI prop-getter pattern. Svelte 5 has no props object to merge at
runtime and no ref forwarding (`bind:this` is direct). Prop-getter APIs need converting to
**attachments/actions** (`{@attach ...}` / `use:`) that apply attributes and listeners directly
to an element.

### 6.6 `ReactNode` props are slots, but often *conditional* slots

Hundreds of props are typed `ReactNode` (`icon`, `label`, `endContent`, `description`,
`emptyState`, `footer`…). Most map to `Snippet`. Two complications:

1. Many accept **either a string or a node** (`label`, `description`, `tooltip`). Svelte props
   should accept `string | Snippet` and the component must branch — worth a shared helper.
2. `utils/isRenderable.ts` uses `isValidElement` to decide whether a slot is "empty" and should
   collapse. There is no Svelte equivalent; empty-snippet detection has to become an explicit
   prop or a `children === undefined` check.

### 6.7 `createPortal` (Chat only) and the native Popover API (everywhere else)

Good news: the overlay system uses the **native Popover API + CSS anchor positioning**, not
React portals — so `Popover`, `Tooltip`, `HoverCard`, `Dialog`, `Toast`, `Lightbox`,
`CommandPalette`, `MobileNav`, `ContextMenu` and `AlertDialog` need no portal shim at all; the
element stays in place in the DOM and the browser promotes it to the top layer.

`Chat` is the only `createPortal` user (×3). Port those with a Svelte action that moves a node,
or restructure to native popover.

### 6.8 `<canvas>` and imperative rendering

| Site | Detail |
|---|---|
| `Spinner` | Draws the spinner into a `<canvas>` 2D context on a rAF loop, reading `getComputedStyle(canvas).color` for `shade="inherit"`. Since `Spinner` has 15 dependents (every loading button/input), this must be right early. Consider whether an SVG/CSS reimplementation is acceptable — that is a **visual-fidelity decision**, not a technical one. |
| `hooks/useImageMode` | Samples pixels via `OffscreenCanvas` + APCA lightness to auto-pick light/dark. Pure logic; ports directly. |

### 6.9 `'use client'` directives

Nearly every file starts with `'use client'` (an RSC boundary marker). These simply disappear —
but the *reason* they exist matters: it flags which components touch the DOM at all. In
SvelteKit the equivalent concern is SSR-safety: `matchMedia`, `navigator`, `ResizeObserver`,
`MutationObserver`, `IntersectionObserver`, `SpeechRecognition`, `OffscreenCanvas` and
`useSyncExternalStore`-backed platform detection (`Kbd`, `Overlay`, `theme`, `Table`) all need
`browser` guards or `onMount` placement.

### 6.10 Concurrent-React niceties

`useTransition`/`startTransition` (11 units), `useDeferredValue`, `useInsertionEffect`
(`CodeBlock`, `theme`), `useSyncExternalStore` (`Kbd`, `Overlay`, `Table`, `theme`, `hooks`) and
`useId` (used in ~30 units for ARIA wiring) all need Svelte stand-ins. `useId` is the important
one — SSR/CSR id stability drives every `aria-labelledby`/`aria-describedby` link in the
library. SvelteKit has no built-in `useId`; a deterministic per-instance id generator must be
part of the foundation.
